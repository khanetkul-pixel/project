# Smart Parking · ระบบลานจอดรถ (Next.js)

เว็บแอปที่สร้างจากงานออกแบบใน Figma หน้า **"ต้นฉบับ (สำเนา)"** ครบทุกหน้า
ใช้ Next.js (App Router) + TypeScript + CSS ธรรมดา ไม่ต้องติดตั้งไลบรารีอื่นนอกจาก Next.js และ React

## วิธีรัน

ต้องมี [Node.js](https://nodejs.org) เวอร์ชัน 18.18 ขึ้นไป (แนะนำ 20 หรือ 22)

```bash
npm install      # ติดตั้งครั้งแรกครั้งเดียว
npm run dev      # เปิดโหมดพัฒนา แล้วเข้า http://localhost:3000
```

สร้างเวอร์ชันใช้งานจริง:

```bash
npm run build
npm start
```

## การเข้าสู่ระบบ

- หน้า Login ไม่แสดงรายชื่อบัญชี — **ดูชื่อผู้ใช้/รหัสผ่านได้ในไฟล์ `lib/accounts.ts`**
- **แก้อีเมล / ชื่อผู้ใช้ / รหัสผ่าน ใน `lib/accounts.ts` แล้วบันทึกไฟล์ → เข้าสู่ระบบด้วยค่าใหม่ได้ทันที ไม่ต้องรีเซ็ต**
  (ค่าที่แก้ใน code ชนะเสมอ ส่วนช่องที่ไม่ได้แก้ใน code จะเก็บค่าที่แก้ผ่านหน้า "สิทธิ์ผู้ดูแลระบบ" ไว้)
- เข้าได้ทั้งด้วย **อีเมล** หรือ **ชื่อผู้ใช้** (คำหน้า @)
- มี 3 บทบาท: Super Admin · เจ้าหน้าที่ · ผู้ดูรายงาน — แถบเมนูจะแสดงเฉพาะหน้าที่บทบาทนั้นเข้าได้
  ถ้าเปิด URL ของหน้าที่ไม่มีสิทธิ์ จะขึ้น "ไม่มีสิทธิ์เข้าหน้านี้"
- บัญชีที่ถูก "ปิดใช้งาน" เข้าสู่ระบบไม่ได้
- หน้า **สิทธิ์ผู้ดูแลระบบ** เพิ่ม/แก้ไข/ลบบัญชี และติ๊กสิทธิ์ตามบทบาทได้ (บันทึกในเบราว์เซอร์)
  ปุ่ม "รีเซ็ตข้อมูลตัวอย่าง" จะคืนค่าทุกอย่างกลับเป็นค่าเริ่มต้นในไฟล์ `lib/accounts.ts`

## ข้อมูลรถใช้ร่วมกันทุกเครื่อง

ทะเบียนที่ค้นหา/ชำระในหน้า `/pay` และรถที่บันทึกเข้าในหน้ารายงาน เก็บไว้ที่ **เซิร์ฟเวอร์ชุดเดียว**
(ไฟล์ `.data/vehicles.json` สร้างให้เองตอนเปิดครั้งแรก พร้อมรถตัวอย่างเต็มผังลานจอด)
อัตราค่าจอดก็เก็บที่เซิร์ฟเวอร์เช่นกัน (`.data/rates.json`) — แอดมินแก้ที่คอม มือถือลูกค้าคิดเงินตามได้เลย

> เคยรันเวอร์ชันเก่ามาก่อน? กด "รีเซ็ตข้อมูลตัวอย่าง" ในหน้าสิทธิ์ผู้ดูแล (หรือลบโฟลเดอร์ `.data`) ให้ได้ข้อมูลตัวอย่างชุดใหม่

- ลูกค้าหลายคนเปิด `/pay` จากมือถือคนละเครื่อง → จ่ายเงินแล้ว สถานะเปลี่ยนเป็น "ชำระแล้ว · รอออก"
- หน้า **รายงาน › รายการรถเข้า-ออก** ดึงข้อมูลใหม่เองทุก 5 วินาที เห็นรถทุกคัน ค้นหาทะเบียน และส่งออก Excel ได้
- ปุ่ม **+ บันทึกรถเข้า** เพิ่มรถใหม่ (ทะเบียน · จังหวัด · ประเภท · ชั้น · ช่อง) ระบบกันทะเบียนซ้ำ ช่องที่มีรถอยู่แล้ว และช่องที่ไม่มีอยู่จริง
- **ผังลานจอด · Dashboard (การ์ดรถในลาน/ช่องว่าง) · หน้าจำลองประตู `/gate`** สร้างจากข้อมูลรถจริง อัปเดตเองทุก 5 วินาที
- **ทางออกที่ `/gate`:** ถ้ายังไม่จ่าย หรือจ่ายแล้วแต่ออกเกินเวลาที่กำหนด ไม้กั้นไม่เปิด และแสดงยอดที่ต้องจ่าย
- เซิร์ฟเวอร์คิดยอดเงินเองตอนบันทึกการชำระ ไม่เชื่อยอดที่หน้าเว็บส่งมา
- ปุ่ม "รีเซ็ตข้อมูลตัวอย่าง" ในหน้าสิทธิ์ผู้ดูแล จะล้างข้อมูลรถกลับเป็นค่าเริ่มต้นด้วย

ให้มือถือในวง Wi-Fi เดียวกันเข้าได้: รัน `npm run dev -- -H 0.0.0.0` แล้วเปิด `http://<IP เครื่องคอม>:3000/pay`

API: `GET /api/vehicles` (ทั้งหมด) · `GET /api/vehicles?plate=1กก1122` · `POST /api/vehicles` (บันทึกรถเข้า) ·
`POST /api/vehicles/<id>/pay` (บันทึกการชำระ) · `POST /api/vehicles/<id>/exit` (บันทึกรถออก) · `DELETE /api/vehicles` (รีเซ็ต) ·
`GET/PUT/DELETE /api/rates` (อัตราค่าจอด)

> ⚠️ ไฟล์ `.data` ใช้ได้เมื่อรันบนเครื่องตัวเองหรือเซิร์ฟเวอร์ที่มีดิสก์ถาวร ถ้านำขึ้น Vercel ให้เปลี่ยน `lib/vehicle-store.ts`
> ไปใช้ฐานข้อมูลจริง (เช่น PostgreSQL / Supabase / Firebase) — ฟังก์ชันอื่นไม่ต้องแก้

## อ่านโค้ดเริ่มจากตรงไหน (สำหรับมือใหม่)

ทุกไฟล์มีคำอธิบายภาษาไทยอยู่บนสุด บอกว่าไฟล์นี้ทำอะไร ใช้ที่หน้าไหน แนะนำให้อ่านตามลำดับนี้

1. `lib/vehicles.ts` · ข้อมูลรถ 1 คันมีอะไรบ้าง สถานะรถ และสูตร "ยอดที่ต้องจ่าย"
2. `lib/fee.ts` · สูตรคิดค่าจอด (มีตัวอย่างการคำนวณในคอมเมนต์)
3. `lib/lot.ts` · ชั้นและช่องจอด และสร้างผังจากข้อมูลรถยังไง
4. `app/api/vehicles/route.ts` · เซิร์ฟเวอร์รับคำขอบันทึกรถเข้า แล้วตรวจอะไรบ้าง
5. `lib/vehicle-api.ts` · หน้าเว็บเรียกเซิร์ฟเวอร์ยังไง
6. หน้าเว็บที่ง่ายที่สุด: `app/pay/page.tsx` (ค้นหาทะเบียน) → `app/pay/[plate]/page.tsx` (รายละเอียด)

**การไหลของข้อมูล (ตัวอย่าง: ลูกค้าจ่ายเงิน)**

```
หน้า /pay/.../qr  →  payVehicle()        →  POST /api/vehicles/<id>/pay  →  .data/vehicles.json
 (หน้าเว็บ)          (lib/vehicle-api.ts)     (app/api/.../pay/route.ts)       (ไฟล์เก็บข้อมูล)
```

ไฟล์ที่ไม่ต้องอ่านก็ได้: `lib/xlsx.ts` (สร้างไฟล์ Excel ระดับไบต์) และ `components/Icon.tsx` (รูปไอคอน)

## แก้ไขลานจอด: ชั้น · แถว · ช่อง · สถานะช่อง

เข้า Admin › ผังลานจอด แล้วกดปุ่ม **"แก้ไขลานจอด"** (ไอคอนเฟือง) มุมขวาบน

**แถวและช่อง:** แต่ละแถวมีจำนวนช่องไม่เท่ากันได้
- กดปุ่ม **+** ท้ายแถว → เพิ่ม 1 ช่อง (เลขช่องต่อจากเลขสูงสุดของชั้น เช่น มีถึง A16 → A17) · แถวละไม่เกิน 12 ช่อง
- ใต้ผัง ใส่จำนวนช่องแล้วกด **"เพิ่มแถว"** → แถวใหม่ท้ายชั้น มีทางวิ่งคั่นทุกแถว · ชั้นละไม่เกิน 8 แถว
- กด **"ลบแถว"** ใต้แถว → ลบทั้งแถว (ต้องไม่มีรถจอด)
- เลือกเครื่องมือ **"ลบช่อง"** แล้วกดช่อง → ลบช่องนั้น (ต้องไม่มีรถจอด) แถวที่ว่างหมดจะหายไปเอง

**เพิ่มชั้น:** ใส่ชื่อชั้น (ไม่ใส่ก็ได้) และจำนวนช่อง (1–40) ในกล่อง "เพิ่มชั้น" ด้านซ้าย แล้วกด "เพิ่มชั้น"
ชั้นใหม่ได้ตัวอักษรนำหน้าช่องถัดไปเอง เช่น ชั้น 4 = ช่อง D01, D02, … (เพิ่มได้สูงสุด 10 ชั้น)

**ลบชั้น:** เลือกชั้นทางซ้าย แล้วกด "ลบชั้นนี้" ที่หัวผัง · ลบได้เฉพาะชั้นที่ไม่มีรถจอด และต้องเหลืออย่างน้อย 1 ชั้น
การตั้งค่าชั้นเก็บที่ `.data/lot.json` · API: `GET/POST/DELETE /api/lot` (POST มีคำสั่ง addFloor · addRow · addSlot · removeSlot · removeRow)

**บังคับสถานะช่อง (มีรถ / ว่าง / ปิดซ่อม):** ในโหมดแก้ไข เลือกเครื่องมือในแถบสีเหลือง แล้วกดช่อง
- **มีรถ** → ใส่รถจำลองทะเบียนสุ่มลงช่องนั้น (บันทึกเป็นรถเข้าจริง เห็นในรายงานด้วย)
- **ว่าง** → เอารถออกจากช่องทันที (ไม่ตรวจการจ่าย เพราะเป็นการจำลอง) หรือเปิดช่องที่ปิดซ่อม
- **ปิดซ่อม** → ดูหัวข้อถัดไป
- ปุ่ม **"เติมรถทั้งชั้น"** / **"ทำให้ว่างทั้งชั้น"** ใช้กับชั้นที่เลือกอยู่

**ช่องซ่อม:**

1. อยู่ในโหมดตั้งค่าเดียวกัน
2. พิมพ์เหตุผลก่อนก็ได้ (เช่น "พื้นแตก") แล้ว **กดช่องว่าง** → ช่องนั้นเปลี่ยนเป็นลายทาง "ปิดซ่อม"
3. **กดช่องที่ปิดซ่อม** อีกครั้ง (หรือกด "เปิดใช้งาน" ในกล่อง "ช่องที่ปิดซ่อม" ด้านซ้าย) → กลับมาใช้ได้
4. กด **"เสร็จสิ้น"** เพื่อออกจากโหมดตั้งค่า

ช่องที่ปิดซ่อม: บันทึกรถเข้าไม่ได้ · ไม่นับเป็นช่องว่างใน Dashboard และจอที่ตู้ · ช่องที่มีรถจอดอยู่ปิดซ่อมไม่ได้
ข้อมูลเก็บที่ `.data/maintenance.json` (ทุกเครื่องเห็นเหมือนกัน) · API: `GET/POST/DELETE /api/maintenance`

## หน้าจำลองประตู `/gate` (สำหรับนำเสนอ)

รวมจอทางเข้าและทางออกไว้หน้าเดียว มีภาพรถวิ่ง ตู้ Kiosk อ่านทะเบียน ไฟสัญญาณ และไม้กั้นยกขึ้น-ลง

- **ทางเข้า:** พิมพ์ทะเบียน (หรือเว้นว่างให้สุ่ม) → กด "รถมาถึงทางเข้า" → ตู้ Kiosk อ่านทะเบียน → ระบบแนะนำชั้นที่ว่างที่สุด → ไม้กั้นยก → รถเข้าลาน
- **ทางออก:** เลือกรถ → กด "รถมาถึงทางออก" → คิดค่าจอด → แสดง QR → กด "จำลองลูกค้าสแกนจ่าย" → ไม้กั้นยก → รถออก
  (คันที่ชำระแล้วหรืออยู่ในช่วงจอดฟรีจะออกได้เลย · กด "ยกเลิก" รถจะถอยออกและไม้กั้นไม่เปิด)
- ทุกขั้นตอนบันทึกลงข้อมูลจริง ถ้าเปิด `/admin/parking-map` ไว้อีกแท็บ จะเห็นช่องจอดเปลี่ยนตาม
- ปุ่ม "เปิดหน้าชำระเงินลูกค้า" เปิด `/pay` ในแท็บใหม่

## สิ่งที่ทำงานได้จริงแล้ว

- คิดค่าจอดจากอัตราในหน้า **อัตราค่าจอด** (ฟรี 15 นาทีแรก · ชั่วโมงละ ฿20 · ปัดขึ้นเป็นชั่วโมง · เพดาน ฿200/วัน)
  แก้อัตราแล้วทุกเครื่องคิดเงินตาม (บันทึกที่เซิร์ฟเวอร์ พร้อมประวัติว่าใครแก้)
- ปฏิทินเลือกช่วงวันที่: วันนี้ / สัปดาห์นี้ / เดือนนี้ / กำหนดเอง (คลิกวันเริ่มต้นแล้ววันสิ้นสุด)
- เลือกชั้นในหน้าผังลานจอด, ค้นหาทะเบียน, ติ๊กสิทธิ์รายเมนู
- **ส่งออก Excel (.xlsx) จริง** ไม่ต้องติดตั้งไลบรารีเพิ่ม (โค้ดอยู่ที่ `lib/xlsx.ts`)
  - รายงานกิจกรรม → ชีต "รายการรถเข้า-ออก" (ส่งออกตามคำค้นหาทะเบียน) + ชีต "สรุป"
  - รายงานการเงิน → ชีต สรุป · รายรับรายวัน · ช่องทางการชำระ · รายการชำระล่าสุด · ชำระผ่านหน้า pay (ข้อมูลจริง)
  - ตัวเลข เงิน และวันที่เป็นค่าจริงใน Excel (เรียง บวก กรองได้) มีหัวตารางสีเขียว ตรึงแถวหัว และปุ่มกรอง
- หน้าชำระ ThaiQR จำลองว่าธนาคารยืนยันการจ่ายหลัง 6 วินาที แล้วบันทึกการชำระลงข้อมูลกลาง และไปหน้าสำเร็จเอง
  (ถ้าออกจากหน้าก่อนครบเวลา หรือ QR หมดอายุ จะไม่บันทึก)
- ข้อมูลรถใช้ร่วมกันทุกเครื่อง (ดูหัวข้อด้านบน)

## สิ่งที่ยังเป็นข้อมูลตัวอย่าง (ต้องต่อระบบจริงภายหลัง)

- กราฟ heat map รายรับใน Dashboard และรายงานการเงิน เป็นข้อมูลจำลอง (`lib/data.ts`, `lib/finance.ts`) — รายรับของ Dashboard กับรายงานการเงินคำนวณจากสูตรเดียวกัน ตัวเลขจึงตรงกัน
- API ยังไม่ตรวจการเข้าสู่ระบบ (ใครเปิดเว็บได้ก็เรียก API ได้ เช่นรีเซ็ตข้อมูล) — ต้องทำระบบ login ฝั่งเซิร์ฟเวอร์ก่อนใช้จริง
- ข้อมูลรถเก็บเป็นไฟล์ JSON — ระบบจริงควรเปลี่ยนเป็นฐานข้อมูล และให้ตู้ Kiosk ที่ประตูเรียก `POST /api/vehicles` เอง
- การเข้าสู่ระบบตรวจรหัสผ่านในเบราว์เซอร์จากรายชื่อใน `lib/accounts.ts` — ระบบจริงต้องตรวจที่เซิร์ฟเวอร์ และเก็บรหัสผ่านแบบเข้ารหัส (hash)
- QR ในหน้าชำระเงินเป็นลายจำลอง — ระบบจริงต้องสร้าง PromptPay/ThaiQR payload ตามมาตรฐานธนาคาร
- การอ่านทะเบียนของตู้ Kiosk เป็นการจำลอง — ระบบจริงต่อเครื่องอ่านทะเบียนที่ตู้ภายหลัง
- "วันนี้" ของทุกหน้า = วันเวลาจริงตอนเปิดเว็บ (`today()` ใน `lib/data.ts`)
